# 實驗紀錄 (Experiment Log)

> 每週更新一次，對應 `docs/project-plan-detailed.md` 的週次規劃。

> 目的：報告撰寫階段(第8週)不需要回頭翻git history找數字，所有關鍵設定/結果/決策都在這裡。

> **統計方法**：每個條件以多個 seed 各訓練一次（主實驗 seed 0–9；Week 5 語意剪枝、PageRank 組與隨機對照為 seed 0–4）；同一 seed 的兩個條件互相配對，對配對差做雙尾 paired t 檢定，並報告配對差的 95% 信賴區間（t 分佈）。p 值只反映訓練隨機性（初始化與抽樣），不代表推廣到其他使用者群體，因為 test 固定為同一批約 973 位 user。完整的配對差、信賴區間與 p 值見 [`results/paired_ci_table.md`](./results/paired_ci_table.md)（由 `scripts/paired_ci_table.py` 產生）。

> **多重比較**：主要結論只依賴下列直接對應研究問題的比較——增強 vs α=0（兩端與只 item，20% / 50% / 100%，共 12 個檢定，Bonferroni 門檻 0.05/12≈0.004）。其餘比較（user-only、α 掃描、Week 5 的各種去噪變體與隨機對照）視為探索性，p 值未經校正，僅作方向性證據。邊緣顯著的結果（例如兩端 20% 的 NDCG，p=0.028）不視為主要發現。

- Valid recall@20 在 epoch30 後開始震盪、不再進步，train loss 仍持續下降 → 典型過擬合訊號，early stopping 正確地保留了 epoch30 的權重而非最終權重

- 評估時必須同時排除 train 與 valid 的已互動項目才能正確計算 test 指標，否則 valid 正樣本會佔掉 test top-K 名額、變相低估指標——這點若第4-5週要重跑evaluate要記得延用同樣邏輯
- 此結果為第4週LLM增強效果的比較基準（baseline）

## Week 3（10/6–10/12）LLM增強 — Prompt設計與小規模驗證

**完成項目**
- [x] User profiling prompt / item attribute prompt 設計（JSON輸出格式 + 1個few-shot範例）
- [x] 小規模驗證：n_users=100, n_items=100（`src/llm_augmentation/run_week3_pilot.py`）
- [x] Parser + retry機制（`src/llm_augmentation/ollama_client.py`）
- [x] 依驗證結果修正prompt（rating_tendency加值域約束、system prompt補繁體中文強制指示）

**第一輪驗證結果（修正前，n=100/100）**

| 任務 | 首次成功率 | Retry後成功率 | 平均耗時/筆 |
|---|---|---|---|
| User profiling | 100% | 100% | 4.33秒 |
| Item attribute | 99% | 100% | 3.64秒 |

格式穩定率（欄位是否齊全）遠超90%門檻，但人工檢查發現「欄位有填、但值不合理/不受控」的問題，被原本的成功率定義蓋掉了，因此又做了第二輪分析：

**內容合理性問題（第一輪，n=100 user profiles）**
1. `guessed_age_group`：99/100 都填`"unknown"`，只有1筆願意猜。代表這個欄位對後續embedding貢獻有限，也無法拿真實`users.dat`的Age欄位做交叉驗證——考慮Week4整合時是否保留這個欄位。
2. `rating_tendency`：雖然prompt/few-shot只示範`generous`一種用詞，實際卻跑出9種不同用詞（generous 75、moderate 7、balanced 4、mixed 4、cautious 3、neutral 2、conservative 2、critical 2、average 1），而原本的成功率算法只檢查欄位存在、不檢查值是否合法，沒能抓出這個格式漂移。
3. 用歷史評分平均值反查`rating_tendency`是否合理：8/100筆標成`"generous"`（寬容）但實際平均評分低於3分（最低到2.4分），顯示模型偶爾被少數幾筆評分帶偏、沒有正確權衡全部歷史。

**內容合理性問題（第一輪，n=100 item attributes）**
1. 格式面：100%成功（99首次+1次retry）。
2. `target_audience`為自由文字欄位，100筆跑出48種不同用詞（例如「成年觀眾」「成人」「成人觀眾」語意重複但字面不同），若之後要拿這欄位做類別特徵需要額外正規化/分群。
3. `supplementary_genres`：89/100為空陣列，代表ML-1M原生的18類標籤已經相當完整，LLM能補充的新資訊有限（少數補到的如"Family"、"Cyberpunk"算合理）。
4. 抓到1筆輸出出現簡體字（"时尚"），原因是原本的system prompt沒有像Week1 `test_ollama.py`一樣明確要求繁體中文。

**修正動作**
- `prompts.py`：`rating_tendency`欄位在system prompt中明確限制為`generous`/`critical`/`neutral`三選一，並提示模型要通盤考量全部評分紀錄再判斷；user/item兩支system prompt都補上「請全程使用繁體中文回答，絕對不可出現任何簡體字」。
- `ollama_client.py`：`query_with_retry`新增`enum_checks`參數，成功判定除了「必要欄位齊全」外，再加一層「指定欄位的值必須落在允許集合內」，值不合法會觸發retry並在prompt中點名是哪個欄位、允許值有哪些。

**第二輪驗證結果（修正後，重新跑n_users=100/n_items=100）**

| 任務 | 首次成功率 | Retry後成功率 | 平均耗時/筆 |
|---|---|---|---|
| User profiling | 100% | 100% | 4.19秒 |
| Item attribute | 100% | 100% | 3.61秒 |

修正效果驗證：
1. **`rating_tendency`值域收斂成功**：100筆全部落在`generous`/`critical`/`neutral`三選一內（neutral 54、generous 24、critical 22），不再出現moderate/mixed/cautious等9種漂移用詞，`enum_checks`確實有效。
2. **與實際平均評分的矛盾筆數大幅下降**：8/100 → **2/100**（且這2筆都是`critical`對到平均分3.53，非常貼近3.5的判定門檻，可視為邊界案例而非明顯誤判），比第一輪的「標generous但平均只有2.4分」這種明顯矛盾好上不少。
3. **繁體中文指示仍有極少數殘留**：user側1/100筆（`profile_summary`混雜簡體字，如「类型」「悬疑」「评价」）、item側2/100筆（如「Song of the South」的`时光`/`爱好者`；「Art of War」甚至出現亂碼替代字元`�`，疑似模型生成了非常規字元）。強制指示把問題從沒設下限壓到約1-2%，但沒有完全消除——如果後續要做全量生成，可以在parser裡加一層簡體字偵測+自動剔除該筆重試（作法類似`enum_checks`），或接受這個殘留率當作已知噪音來源。
4. **`guessed_age_group`（98/100 unknown）與`target_audience`高分歧（41種不同用詞）、`supplementary_genres`（89/100空）這三個第一輪就觀察到的模式，這輪沒有特別去修，結果也維持相近水準**，符合預期（這輪只鎖定rating_tendency和繁體中文兩個問題修正）。

**觀察/決策**
- 「格式穩定率」若只檢查JSON能不能parse+欄位是否存在，並不足以代表輸出品質，值域是否合法要另外檢查——這點會寫進報告的方法論限制/反思段落。
- `guessed_age_group`低利用率、`supplementary_genres`低命中率，這兩點可以直接呼應報告的核心敘事「LLM增強不是每個欄位都有效，過量/不精準的欄位設計本身就是一種噪音來源」，跟第5週去噪分析的主題互相呼應。
- 第二輪驗證後，格式穩定率與內容合理性都已達標（rating_tendency矛盾率8%→2%、值域100%收斂），殘留的1-2%簡體字/亂碼問題規模很小，決定不再花時間在Week3打磨，**帶著已知的殘留噪音進入Week4全量生成**，這個殘留率本身也可以寫進報告當作「即使有值域約束，開源小模型仍有低機率的格式/語言漂移」的量化佐證。

**設計決策**
- **防資料洩漏**：Week 4 的 user 歷史只取 `train.csv` 內的互動（以 train 的 (user, item) 配對對應 `ratings.dat` 取評分，再取最近 15 筆）。Week 3 pilot 是直接取 `ratings.dat` 的最近 15 筆，在全域時間切分下會把 valid/test 期間的評分餵給 LLM（資料洩漏）；pilot 結果僅用於 prompt 設計，不用於評估。item 端只用片名與類型，無此問題。
- **整合公式**：`e0_user = id_emb(u) + α · mask_u · W_u · llm_emb(u)`；item 同理。LLM 向量凍結（已 L2 normalize），只訓練線性投影 W（無 bias，512→64）；`mask=0`（未生成或不在目前比例內）等同 baseline；`α=0` 與純 LightGCN 數學等價（已閱讀程式確認，Linear 層在 embedding 初始化之後才建立）。L2 正則只作用於 ID embedding，W 無正則（可能與 α 過大時不穩定有關，尚未驗證）。
- **embedding 文字**：只用 LLM 產出欄位（user：偏好/不喜歡類型、評分傾向、摘要；item：氛圍標籤、適合觀眾、補充類型、摘要），不含 `guessed_age_group`（Week 3 pilot 98/100 為 unknown）。預設保留 `dirty` 筆數。
- **評估協定**：valid 排除 train；test 排除 train∪valid（與 baseline 相同）。主實驗改為「固定訓練 25 epoch、不做 early stopping」（見觀察），α=1.0 為事前指定的主設定。
- **訓練耗時**：固定 25 epoch 每次約 265 秒（4.4 分鐘；`train_sec` 平均值，兩端皆增強的各組為 265–270 秒，只增強 user 約 257 秒、只增強 item 約 266 秒，α=0.3 / 3.0 的 10 次約 333 秒，原因未查）；115 次固定 epoch 實驗合計約 8.7 小時。
- **控制組**：以同協定下的 α=0 為基準；Week 2 的單次 baseline（early stopping，0.0814 / 0.2721）僅供參考，停止規則不同，不與之直接比較。

### 觀察/決策
 
- **增強有效但幅度小**：ratio=1.0 時 Recall 相對 +4.7%、NDCG 相對 +1.8%（皆 p<0.001，依 seed 配對）；20% 時 Recall 已有穩定的小幅增益（+2.3%，10/10 seed 為正）。
- **先前「不顯著」的原因**：early stopping 的停止點造成大變異，加上 20% 覆蓋時僅約 196 位 test user 被增強。改為固定 25 epoch 後，α=0 的標準差由 0.0018 降到 0.0006。25 epoch 取自 valid 曲線多數 run 的最佳 epoch（20–30），非依 test 選擇。
- **報酬遞減**：Recall 在 50% 附近飽和（50% 取得約 91% 的增益、約 49% 的生成耗時；50%→100% 的 Recall 差異偵測不到）；NDCG 到 100% 仍顯著上升（50% 僅達約 55%）。「偵測不到」不等於「沒有」，上界約 +0.0012。
- **增益主要來自 item 端**：只增強 item 取得兩端增益的約 73%（Recall）/ 87%（NDCG），生成耗時約為全部的 39%；user 端 Recall 不顯著、NDCG 邊緣顯著（多重比較下不視為穩健）；兩端相加無明顯協同。沒被增強的 user 也有 Recall 增益（ratio 0.5：+0.0016），與 item 向量為全體共用、經圖傳播一致。
- **α 在 0.3–1.0 為平台，3.0 過大**：α=3.0 的 NDCG 增益消失且變異最大，Recall 增益仍在（+0.0037，5 seed）。α=1.0 為事前指定，掃描僅作敏感度分析，不據此挑選「最佳 α」（避免在 test set 上調參）。
- **噪音率穩定**：dirty 與 retry 比例不隨生成量增加而惡化；items 的 retry>1 比例（約 10–12%）約為 users（約 3%）的 3–4 倍。
- **item-only 的 Recall 在 50% 達到高點，之後略降（-0.0006，p=0.048，邊緣顯著，不視為穩健），NDCG 仍顯著上升（+0.0019，10/10）**：把更多 item 加入增強，似乎是以小幅 Recall 換取排序品質。「兩端」曲線的 Recall 在 50%→100% 持平，與此一致。
- **商業建議（本實驗條件下）**：優先生成 item 屬性；若以找回相關項目（Recall）為主，約 50% 的 item 即達高點（1.9 小時，約為兩端 100% 成本的 19%）；若重視排序品質（NDCG），item 增強到 100%（3.8 小時）仍有收益；user profiling 的投資報酬率低（兩端 vs 只 item 偵測不到穩定差異，成本多 2.6 倍）。
- **敘事修正**：Week 3 預設的「增強越多越有害」未獲數據支持，實際為報酬遞減（Recall）或持續上升（NDCG）；噪音議題已於 Week 5 以剔除低品質生成檢驗，結果見 Week 5。

### 限制
 
- 檢定的 p 值與信賴區間只反映訓練隨機性（test 固定為同一批 973 位 user），不代表推廣到其他使用者群體。
- 效果量小（絕對 +0.0037 Recall）；多個比較同時進行，主要結論（Recall 於三個比例、NDCG 於 50%/100%、item-only）穩健，邊緣顯著的結果（如 20% 的 NDCG、user-only 的 NDCG）不視為主要發現。
- 比例同時改變 user 與 item 覆蓋（兩端曲線）；ablation 主要在 ratio=1.0、α=1.0 完成，user-only 另測 α=3.0（僅 5 seed），user-only 的 α=0.3 未測。item 的增強子集為隨機抽樣（`order.json`），未依熱門度或冷啟動程度挑選。
- user profile 僅取最近 15 筆 train 評分；結論僅限 MovieLens-1M、本 prompt 與 `qwen2.5:7b-instruct-q4_K_M`；成本只計本地 GPU 生成時間（單 worker）。
- 評估集僅 973 位重度使用者。
- 以下為推測、尚未驗證：user profile 與互動圖資訊重複導致 user 端增益低；W 無正則造成 α 過大時不穩定；100% 階段 users 每筆變慢的原因。
- 多重比較：Week 4 的主要比較（增強 vs α=0，兩端與只 item 各三個比例，共 12 個檢定）以 Bonferroni 門檻約 0.004 判讀，其中兩端 20% 的 NDCG（p=0.028）與只 item 20% 的 NDCG（p=0.17）未通過；user-only、α 掃描與兩端 vs 只 item 的比較為探索性，未經校正，僅作方向性證據。

### 觀察/決策
 
- **去噪沒有額外益處。** 無論依格式（A、B）或依語意一致性（prune10/20）剔除，Recall 相對未過濾版皆無穩健差異；所有去噪版本相對 α=0 的增益都保留（Recall +3.6%、NDCG +1.3%～+1.4%），表示增強本身穩健，而不是依賴被剔除的那些 item。
- **NDCG 在六個剔除變體（A、B、prune10/20、rand10/20）的點估計全部低於未過濾版**（−0.0005～−0.0026），連隨機剔除也是。這與 Week 4「item 端 NDCG 隨增強覆蓋增加而持續上升」一致：剔除越多 item，被增強的 item 越少，NDCG 就越低。換言之，NDCG 的下降主要可由「增強覆蓋減少」解釋，而非噪音被移除的副作用。
- **語意剪枝沒有比隨機剔除好，在 NDCG 上反而較差**（prune20 − rand20：−0.0018，5/5 seed 為負）。推測（未驗證）：與同類型中心距離最遠的 item，可能是類型罕見或內容獨特、對排序仍有資訊量的 item，而不是壞資料。被剔除者在 Documentary、Children's、War 等小類型中占比偏高，與此推測方向一致，但尚未直接檢驗這些 item 的排序資訊量。
- **prune10 的 Recall 有微弱訊號（+0.0008，相對未過濾 +0.9%；相對隨機 p=0.051），但 20% 時消失，且 NDCG 同時下降，不視為主要發現。** 本週共做約 16 個「剔除變體 vs 控制」的比較（12 個對未過濾、4 個剪枝對隨機）；以 Bonferroni 校正（0.05/16≈0.003）後，只有「prune20 的 NDCG 低於未過濾版」（p=0.001）仍顯著，其餘（包含 B 的 NDCG p=0.007）僅為方向性證據。
- **隨機對照的抽樣變異與效果同量級。** rand10 的 NDCG 差（−0.0015）比 rand20（−0.0008）更差，不合單調預期，顯示「丟掉哪些 item」本身就造成 ±0.001 左右的波動；剪枝與隨機的差距（−0.0006～−0.0018）無法完全與此區分。
- **PageRank 在二部圖上就是熱門度，且沒有帶來去噪效果。** PageRank 與 degree 的 Spearman 為 0.9989。剔除 PageRank 最低 30%／50% 的 item（只動到 2.6%／9.0% 的互動），Recall 無變化（+0.0006、+0.0002，p>0.2），NDCG 約 −0.0010（p=0.033、0.064），沒有任何 PageRank 變體優於未過濾版。
- **增強效益取決於「被增強 item 覆蓋的互動比例」，呈飽和型。** Recall：覆蓋約 48% 以上（被剔除互動 ≤ 51.5%）時增益完整保留（rand50 +0.0004，p=0.17）；覆蓋約 20–24% 時剩約一半（rand80、prhigh30，保留 53%、36%）；覆蓋約 9–10% 時增益消失（rand90 的 Recall 0.0784，接近 α=0 的 0.0786）。NDCG 大致隨覆蓋減少而下降，不像 Recall 那樣有平台。
- **相近覆蓋下，PageRank 選擇與隨機沒有可靠差異。** prhigh30（動到 76.5%）對 rand80（動到 80.2%）：Recall −0.0005（p=0.12）、NDCG +0.0002（p=0.64）。修正先前的暫時判讀：prlow50 − rand50 的 NDCG +0.0022（p=0.002）並不代表「PageRank 選得好」，因為 prlow50 只動到 9.0% 的互動，rand50 動到 51.5%，差異可由覆蓋量解釋；prhigh30 − rand30 的 −0.0022／−0.0029 同理（76.5% vs 30.5%）。
- **一個尚未釐清的例外：prhigh50 對 rand90（兩者都動到約 91% 互動）。** prhigh50 保留 1704 個冷門 item 的增強，rand90 只保留 341 個隨機 item，結果 prhigh50 較好（Recall +0.0012，p=0.056，5/5 為正；NDCG +0.0024，p=0.005，5/5 為正）。可能是「被增強的 item 數量」也有影響，或冷門 item 每筆互動的增強價值較高；兩者在本設計下無法區分，rand90 也只用一份名單，視為待驗證的觀察。另外 rand90 的 NDCG 保留增益為 −25%（SE 10%），暗示只增強極少數（10%）item 的 NDCG 可能略低於完全不增強，同樣僅供參考。
- **成本效益（推算）：** 只對 PageRank／熱門度前 50% 的 item 生成（prlow50）可使 item 端生成量約減半，Recall 與完整增強相當（+0.0002，p=0.57）、NDCG 約低 0.0010（−0.4%，p=0.064）；相同生成量下隨機選 50%（rand50）的 NDCG 低 0.0032（p<0.001）。節省的生成時間是依 item 端生成量比例推算（本實驗 100% 生成後再遮罩，未實際以優先順序生成）。
- **敘事結論**：Week 3 預設的「低品質／過量增強資訊會傷害效果」在本實驗條件下未獲支持。LLM 輸出噪音率低（dirty 2.1%、retry>1 約 10%），簡體殘留對 `bge-small-zh` 的語意影響小，被剔除的 item 仍帶有有效資訊。
- **商業建議（本實驗條件下）**：不需要為了「清洗」LLM 輸出而增加過濾步驟或重生成成本，保留全部增強特徵即可；省下的成本優先用於提高 item 端的生成覆蓋（見 Week 4）。若生成預算有限，建議以 item 熱門度（等同 PageRank 排序）由高到低決定生成順序：以約 50% 的生成量即可保留 Recall 增益，NDCG 損失小。

### 限制
 
- 去噪的 A/B 為 10 seed，語意剪枝與隨機對照僅 5 seed，且 t 檢定在 n=5 下檢定力低；p 值只反映訓練隨機性（test 固定為同一批 973 位 user）。
- 隨機剔除對照每個比例只用一份剔除名單（`--seed 0`），結果受該份名單影響；未用多份名單估計其變異。
- 噪音只用兩種操作型定義（格式／字元、類型內語意一致性），沒有人工標註的品質標準，因此只能說「這兩種定義下的過濾無益」，不能斷言「沒有噪音」。
- 結論僅限 MovieLens-1M、本 prompt 與 `qwen2.5:7b-instruct-q4_K_M`、item 端 100%、α=1.0。
- 以下為推測、尚未驗證：A 組被剔除的 item 多為懸疑類用語造成類型偏差；語意離群的 item 對排序有額外資訊。
- PageRank 組只有 5 seed；隨機對照（rand30／50／80／90）各只用一份剔除名單（`--seed 0`），例如 prlow50 − rand50 的差異有一部分可能來自該份名單。PageRank 組共約 28 個檢定（8 個變體 × 2 指標 + 6 個配對比較 × 2 指標），Bonferroni 門檻約 0.05/28≈0.0018；p≈0.002 的結果（rand30 的 NDCG、prlow50 − rand50、prhigh30 的 Recall）在門檻邊緣，只視為方向性證據。
- 本實驗只做 item 層級的篩選（被剔除者退回 ID embedding），並未改變圖結構或傳播權重，因此不能推論「以 PageRank 調整圖傳播權重」的效果。
- PageRank 與 degree 幾乎相同（0.9989），未另跑 degree 對照，因此無法區分「PageRank 本身」與「單純熱門度」。
- 劑量反應圖的保留增益分母很小（見 (15) 備註），SE 約 0.1–0.2；prhigh50 − rand90 的例外解釋（item 數量或冷門 item 的單位互動價值）為推測。

**觀察/決策**
1. **甜蜜點是 item 端約 50%。** 1.9 小時（兩端 100% 時間的 19%）取得 Recall 增益 +0.0032（兩端 100% 的 88%）與 NDCG 增益 +0.0023（48%）。只 item 100% 的 Recall 反而略低（+0.0027；相對 50% 為 −0.0006，p=0.048，邊緣、不視為穩健），NDCG 則持續上升（相對 50% 為 +0.0019，p<0.001，10/10 為正）。
2. **同樣的時間，item 端比兩端划算。** 約 1.9 小時：只 item 50%（Recall +0.0032、NDCG +0.0023）明顯高於兩端 20%（+0.0018、+0.0008）；兩端要 4.8 小時才有相近的 Recall（+0.0033）。
3. **兩端 100% 相對只 item 100% 多花 6.1 小時（2.6 倍時間），多得的增益偵測不到。** Recall +0.0010（p=0.054，8/10 為正）、NDCG +0.0006（p=0.35，7/10 為正）；「偵測不到」不等於「沒有」。
4. **加了去噪後，效益曲線沒有變得更划算。** 格式過濾與語意剪枝沒有提升 Recall、NDCG 略降（Week 5 (12)(13)）；唯一省成本的做法是依熱門度（PageRank 排序）決定生成順序：prlow50 的 Recall 與完整增強相當（+0.0002，p=0.57）、NDCG 低 0.0010（p=0.064），相同生成量的隨機 50%（rand50）NDCG 低 0.0032（p<0.001）（Week 5 (14)）。該節省是由遮罩推算，並非實際以優先順序生成，且僅 5 seed，屬方向性證據。
5. **商業建議（本實驗條件下）**：預算有限時，只對 item 生成約 50%，優先選熱門 item（Recall 約達全量 88%，成本約 19%）；若重視排序品質（NDCG），item 增強到 100%（3.8 小時）仍有收益；user 端 profiling 成本高、增益偵測不到，不建議優先投資；不需要額外的清洗步驟。

**限制**：相對增益僅約 +2%～+5%；test 只有約 973 位 user，p 值只反映訓練隨機性；成本只計本地 GPU 單 worker 生成時間；結論限於 MovieLens-1M、本 prompt 與 `qwen2.5:7b-instruct-q4_K_M`。
